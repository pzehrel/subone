# Domain Docs

本仓库采用单一上下文。`apps/server` 与 `apps/web` 共用根目录领域词汇表和架构决策。

## 探索前阅读

1. 阅读根目录 `GLOSSARY.md`，理解领域术语、含义及 Avoid 说明。
2. 阅读 `docs/adr/` 中与当前工作相关的架构决策。

文件或目录尚不存在时，直接继续当前工作。
术语或架构决策实际明确后，由 `domain-modeling` 技能按需创建或补充相应文档。

## 文档位置

- 领域词汇：`GLOSSARY.md`。
- 架构决策：`docs/adr/NNNN-简短主题.md`。

前后端在同一套文档中记录共同概念和决策。

## 使用领域词汇

Issue 标题、设计讨论、假设、代码和测试中的领域概念采用 `GLOSSARY.md` 定义的术语，遵守其中的 Avoid 说明。

遇到尚未定义的概念时，先检查是否已有对应术语；确有词汇缺口时，记录给 `domain-modeling` 技能处理。

## 架构决策冲突

方案与现有 ADR 冲突时，在输出中明确指出 ADR 编号、冲突内容和重新讨论的理由，供用户决定是否重开该决策。
