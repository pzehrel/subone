# 上游 DoH 属于来源的生效解析结果

上游 DoH 与同批解析节点按一次成功更新整体保存，全部来源节点自动绑定；关系使用来源及节点的稳定身份，避免改名、调序或多来源相同连接破坏绑定。不设置独立 DoH 服务库或人工层级覆盖。

用户于 2026-11-06 确认：上游无 DoH 或移除 DoH 后沿用模板 DNS；多个 DoH 完整保存并按输入顺序映射，目标只能采用一个时取首项并报告降级。目标无法分别表达多来源绑定时保留模板 DNS，并明确列出未生效的绑定，以免任意一个来源覆盖其他来源；本轮仅采用上游及模板明确提供的连接参数，不新增 DoH 出站编辑入口。

客户端能力降级不改变来源意图，也不能掩盖实际采用配置的缺失依赖或循环；模板未被接管的解析服务及规则继续保留。依据：[规格 #14](https://github.com/pzehrel/subone/issues/14) 及本轮用户确认。

用户于 2026-11-07 确认：客户端能力以官方文档和官方配置样例为依据，官方已给出的配置能力可用于输出映射；真实客户端加载验证单独记录，未经官方确认的 Issue 报告不用于否定文档能力。Quantumult X 的[官方样例](https://github.com/crossutility/Quantumult-X/blob/master/sample.conf)已提供按域名指定 DoH 的语法，应据此映射来源节点服务器域名，不再仅因缺少实机验证将所有来源绑定判为未生效。

同日确认本轮覆盖项目支持的全部六种完整输出：Mihomo、sing-box、Loon、Quantumult X、Egern 和 Shadowrocket。同一份输出中，按节点服务器域名汇总相关来源的 DoH，去重合并后用于该域名，所有使用该域名的输出节点共享合并后的解析器，包括自身来源没有 DoH 的节点。只有该域名没有任何上游 DoH 时才沿用模板 DNS；不同来源的 DoH 不再因此视为冲突并回退模板或停止生成。来源中保存的 DoH 绑定保持不变；各客户端采用其原生配置表达上述规则。

用户于 2026-11-13 确认：同域名对应的上游 DoH 作为该域名的共用候选，不新增来源优先级设置。合并去重沿用来源列表顺序及各来源内部的 DoH 顺序，单项输出取合并后的首项；此顺序用于保持输出确定，不表示服务可用性排名。

2026-11-13 在 Quantumult X 1.8.0 build946（macOS）的实测补足能力边界：单项域名限定 DoH、glob 和别名可用；同行多个域名限定 URL 的对照失败，同域拆多行则跟随首条匹配项。用户据此确认 Quantumult X 的兼容输出应保留同域合并后的完整 DoH 列表，每项独立写一行 `doh-server`，保持既定顺序。1.8.0 只使用首条，支持同域叠加的新版可使用多条；旧版只使用首条不要求生成器删除后续行。此决定替代 Quantumult X 先前仅输出首项的方案，不改变其他目标的单项能力规则，也不按服务可用性重排。原首项的间歇 TLS 连接失败另行记录；验证范围和限制见[客户端支持文档](../client-support.md)。

用户同日确认下游配置可附简短注释说明兼容性；在完整多行输出方案中，说明 1.8.0 仅使用首条，不再把已输出的后续服务描述为生成器未采用。生成采用结果按实际写入配置的服务记录，不声明客户端运行效果或服务连通性。来源连接参数无法完整表达时，继续按既有规则保留受影响范围的模板 DNS 并报告原因；不擅自省略参数或重新分配节点使用的 DoH。本轮不调整界面标签，后续 UI 调整先通过原型展示。
