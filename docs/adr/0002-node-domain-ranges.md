# 自动归并节点域名范围并按目标输出

用户于 2026-11-07 确认：全部六种完整输出的节点域名范围由程序从实际配置推导，自动生成 glob 范围，不要求用户逐个填写节点域名或手工维护通配符；本轮不新增 DoH 代理出站适配或编辑入口。来源及节点的 DoH 绑定仍按 ADR 0001 保存，范围归并只作用于下游输出。

程序先将同一完整域名关联来源的 DoH 合并，再按相同有效 DoH 组合归组，依据 DNS 标签层级和上游明确的关联别名生成候选范围。公共后缀表用于限制归并边界，包含私有后缀，不简单截取域名最后两段；公共后缀不能被折叠为一条宽泛规则。候选范围若覆盖已知的不同解析意图、必要引导或 DoH 服务自身域名，则继续细分，必要时保留完整域名。公共后缀及当前未发现冲突不等于证明所有未见子域都属于同一来源。参考：[Public Suffix List](https://publicsuffix.org/learn/)。

本轮只自动归并同父域下使用相同 DoH 组合的同层子域，父域本身单独处理；不把某个客户端的 glob 字符串当作六种输出的共同格式。Mihomo、Quantumult X、Loon、Egern、Shadowrocket 均有官方通配配置依据，但匹配边界及字段不同；sing-box 使用域名、后缀或正则字段，节点解析通过 `domain_resolver` 指定。适配器按目标原生能力输出，必要时由生成程序匹配节点并分配节点 DNS；不能把普通 DNS 规则直接当作已配置节点解析器。官方依据与未明示的语法边界见[客户端支持文档](../client-support.md)。

节点相关别名随成功 DoH 批次保存，后续失败更新的原文不改变该快照。别名目标继承原域名合并后的解析器；实际采用路径中的别名循环或相互矛盾的目标要求修复。

Shadowrocket 的多 DoH 使用一个 `server:` 前缀和逗号分隔的 URL 列表，不加引号；[官方公告](https://t.me/s/ShadowrocketNews?before=1650)确认 Host 多服务器能力，[配置维护者的原始文件](https://github.com/budaobu/rules/blob/b97b9f322c23be5ad0dad096d9bafc9b3e124304/conf/lazy_rocket.conf#L308)给出完整通配 Host 与多 DoH 写法。后者作为语法交叉核对，不称为官方示例。
